## Фактический статус после подключения 20.07.2026

- Активная CMS использует Prisma/PostgreSQL, поэтому добавлен идемпотентный `cms/packages/api/prisma/kz-content-sync.ts`; он заполняет JSON-поля страниц и translation-таблицы из утверждённых пар.
- Главная, страница «Партия туралы», четыре подтверждённых программных блока, история, руководство, три медиапроекта, темы обращений и 20 филиалов заполнены KZ-контентом.
- Полные тексты новостей без KZ-версии намеренно показываются по-русски без пометки. Скрипт не создаёт машинный перевод.
- Для 20 филиалов KZ-названия, ФИО председателей и адреса читаются из той же проверенной SQL-таблицы на стороне сайта; изменение Prisma-схемы для `chairmanKz` не потребовалось.
- `keyword` первых четырёх программных блоков локализуется публичным API как `ЕҢБЕК / СӨЗ / ЗАҢ / АДАМ`.
- Оставшиеся пункты ниже являются реальными фолбэками, а не незавершённым подключением языка.

## Закрытые архитектурные расхождения

| Проблема | Принятое решение |
|---|---|
| В корне репозитория нет `src/`; frontend находится в `app/src/` | Инфраструктура создана и подключена в `app/src/i18n/`. |
| Указанные snake_case-таблицы не являются активной БД | SQL этапа 2 сохранён как контракт, активная база синхронизируется Prisma-скриптом. |
| В `Branch` нет `fullNameKz/chairmanKz` | Сайт использует проверенную таблицу филиалов из миграции; `cityKz/addressKz` заполнены в БД. |
| `Setting` не имеет языковых полей | Локализуемые настройки хранятся в `PageBlock.content`, остальные значения языконезависимы. |
| `ProgramBlock.keyword` не локализован | Публичный API выбирает KZ-keyword по номеру блока. |
| `MediaPublication`, `Testimonial`, `Candidate` не везде имеют языковые поля | При отсутствии точной пары используется RU-фолбэк; причина остаётся в разделах ниже. |

### 1.4 `news`

В источнике есть заголовки 6 fallback-новостей и пары `title/excerpt` для 4 карточек, но нет:

- `content_kz` для всех полнотекстовых новостей в seed/CMS;
- `excerpt_kz` для 6 fallback-новостей из `app/src/lib/data.ts`;
- SEO-полей `seo_title_kz`, `seo_description_kz`, `seo_keywords_kz`;

Фолбэк: соответствующие RU-поля, без пометки и без машинного перевода.

## 4. Что считать закрытым после дополнения источника

Для каждой новой строки в `content/kzversiontext.md` необходимо:

1. Добавить точную пару RU → KZ и место использования в `docs/kz-mapping.md`.
2. Удалить соответствующую запись из этого файла.
3. Не менять RU-оригинал и не нормализовать редактуру перевода самостоятельно.
4. Для динамического контента хранить RU-фолбэк, если KZ-поле `NULL`, пустая строка или версия `lang='kz'` отсутствует.

## 5. Выполненная приёмка

- Production-сборка сайта и TypeScript-сборка API проходят без ошибок.
- Публичные KZ-endpoints программы, руководства, истории, медиапроектов, филиалов и новостей отвечают `200` и возвращают локализованные поля.
- Все 20 филиалов имеют отличающиеся от RU значения `cityKz` и `addressKz`; KZ-ФИО и полные названия берутся из утверждённой таблицы этапа 2.
- Невалидные тестовые запросы форм вступления и обращения корректно отклоняются кодом `400`, не создавая записей.
- Переключатель использует единое состояние `LanguageContext`, сохраняет `npk-language` в `localStorage` и повторно запрашивает контент после смены языка.
