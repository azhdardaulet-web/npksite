# План правок по итогам созвона (16.07.2026)
## Сайт НПК — редизайн главной, тёмная/светлая тема, новая форма вступления

> ## ⚠️ Адаптация под реальный стек (прочитай первым)
>
> Исходный план написан в терминах Supabase, но проект работает на **собственной CMS
> (`cms/`: Express 5 + Prisma + PostgreSQL, админка React, файлы в MinIO)**. Сайт (`app/`)
> уже читает контент через `app/src/lib/api.ts` → `/api/v1/*`, хардкод в секциях — фолбэк.
> Соответствие терминов плана нашему стеку:
>
> | В плане (Supabase) | У нас (cms/) |
> |---|---|
> | таблица `page_blocks` | модель `PageBlock` (страница `home`, блоки по `type`, контент JSON) — фронт читает через `usePageBlocks('home')` |
> | таблица `site_settings` | модель `Setting` (key/value) — публичного эндпоинта пока нет, при необходимости добавить |
> | таблица `branches` | модель `Branch` (новые поля — Prisma-миграцией) |
> | `join_requests` + RLS | модель `JoinRequest` + проверка ролей в middleware Express |
> | Edge Functions (youtube-feed, meet-create, pdf) | роуты/сервисы в `cms/packages/api` (Node), кэш — в `Setting` или в памяти |
> | `supabase/migrations/*.sql` | `cms/packages/api/prisma/migrations/` (`prisma migrate dev`) + seed-скрипты для контента |
> | секреты Supabase | `cms/.env` |
> | pg_cron | node-cron / существующая механика напоминаний в API |
>
> Контентные правки (тексты, счётчики, баннер) вносим через блоки `PageBlock` страницы `home`
> и `Setting` — так заказчик потом правит их из админки (требование п. 4).

**Дедлайн из созвона:** 20–21 июля → **4–5 рабочих дней**. План отсортирован по приоритету: если что-то не влезает — режется снизу.

## Часть 1. Три технических решения (прочитай до промптов)

### 1.1. Где вносить правки: БД или код — железное правило

Сайт уже читает контент из Supabase, хардкод остался фолбэком на случай падения БД. Отсюда:

- **Контент (тексты, цифры, фото, баннер)** → только в БД. Правка в коде не отобразится на сайте и создаст расхождение.
- **Структура (новая секция, удаление блока, форма, тема)** → код.
- **Гибрид (п. 1, 2, 4, 5, 8 из списка):** новые тексты кладём в `page_blocks` / `site_settings`, а кодом меняем только разметку. Бонус: заказчик потом меняет баннер и цифры сам — это его прямое требование из пункта 4.
- Если какой-то текст главной ещё не переехал в БД (hero, тикер, счётчики могли остаться хардкодом после Этапа 3) — **переносим в БД в момент правки**, а не правим хардкод. Этап 1 начинается с аудита, чтобы это выяснить.
- Фолбэк-хардкод не трогаем вообще: он виден только при падении БД, устаревший фолбэк не страшен.

### 1.2. Тёмная/светлая тема без «белого по белому»

Проблема, которой ты боишься (поставили светлый фон — текст слился), возникает, когда цвета прописаны жёстко: `bg-black`, `text-white`, `bg-[#111]`. Решение — **семантические токены**: цвета описываются по роли, а не по значению.

```css
:root {           /* светлая тема */
  --bg: #ffffff;        --surface: #f4f5f7;
  --text: #111318;      --text-muted: #5b6068;
  --border: #e3e5e8;    --accent: #d1272e;  /* красный НПК */
}
.dark {           /* тёмная тема */
  --bg: #0c0d10;        --surface: #16181d;
  --text: #f2f3f5;      --text-muted: #9aa0a8;
  --border: #262930;    --accent: #e5383f;
}
```

В компонентах вместо `bg-black text-white` — `bg-[var(--bg)] text-[var(--text)]` (или семантические классы через tailwind.config). Текст физически не может слиться с фоном: они всегда из одной согласованной пары. Переключение — класс `dark` на `<html>` + localStorage + учёт системной темы.

**Два исключения:** медиа-раздел (/media) по концепции ТЗ всегда тёмный — его из темизации исключаем принудительным `.dark`. Фото и видео от темы не зависят.

### 1.3. Google Meet: как это реально работает

У Meet нет кнопки «создать встречу по API» — ссылка создаётся только через **Google Calendar API** (событие с `conferenceDataVersion=1` возвращает ссылку Meet). Работает и с обычным Google-аккаунтом партии, Workspace не обязателен. Схема:

1. Один раз: OAuth-авторизация Google-аккаунта партии → refresh token → в секреты Supabase.
2. Менеджер приёмной в CMS жмёт «Назначить видеозвонок» у обращения: депутат, дата, время, 30 мин.
3. Edge Function создаёт событие в календаре → получает ссылку Meet → сохраняет в обращении → письмо гражданину и депутату + SMS-напоминание за час (механика из старого плана переиспользуется).

**Про WhatsApp честно:** автоматическая отправка ссылки в WhatsApp = WhatsApp Business API — платная верификация Meta, недели согласований. На дедлайн — email + SMS автоматически, WhatsApp менеджер шлёт вручную (в CMS кнопка «Скопировать сообщение»). Так и озвучь заказчику.

Это **упрощает** старый Этап 7: Daily.co, встроенный звонок и кабинет расписаний не нужны — выкидываем, экономим 2–3 дня.

### 1.4. Как не дать Claude Code снести сайт

1. **Ветка на весь пакет правок** — main остаётся рабочей версией для заказчика.
2. **Коммит после каждого проверенного пункта.** Сломалось — `git checkout .` (10 секунд), а не починка за токены.
3. **В каждом промпте — граница:** «меняй только файлы X, Y; остальное не трогай». Это уже в промптах ниже.
4. **Правило одного экрана:** после каждого промпта открой сайт и посмотри глазами именно тот блок. Не копи непроверенные изменения.
5. Тему (Этап 2) делаем **посекционно с коммитами** — это единственная правка, которая касается всех файлов сразу, поэтому она первая и самая дисциплинированная.
