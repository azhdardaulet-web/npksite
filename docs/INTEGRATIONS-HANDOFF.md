# Инструкция для партнёра-разработчика — что осталось подключить вручную

Один документ на все три внешних интеграции сайта НПК (`npksite`), которые
сейчас работают в dev-режиме / на заглушках и ждут реальных ключей/провайдера.
Вся остальная логика (формы, БД, CMS-админка, письма, напоминания) уже
написана и протестирована — по каждому пункту ниже нужно только то, что
описано в разделе «Что сделать».

Стек, если нужно вспомнить: `app/` — React-сайт, `cms/packages/api` —
Express + Prisma + PostgreSQL (бэкенд CMS), `cms/packages/cms` — React-админка.
Секреты — только в `cms/.env` (список всех переменных с комментариями —
`cms/.env.example`, скопируй оттуда).

---

## 1. SMS-провайдер

**Где используется:**
- Подпись заявления о вступлении в партию — форма `/vstupit` (5-шаговый
  визард), шаг 4 «Подпись»: гражданин вводит код из SMS, заявка помечается
  `phoneVerified: true`.
- Напоминание за 1 час до видеоприёма в приёмной (email-напоминание уже
  реально отправляется, SMS-дубль — по той же функции).

**Что уже сделано:**
- `cms/packages/api/src/lib/sms.ts` — единственная точка входа, функция
  `sendSms({ to, text })`. Сейчас она только пишет код в лог сервера
  (`logger.warn`) — **это осознанный dev-режим**, а не баг: весь остальной
  пайплайн (генерация 6-значного кода, bcrypt-хеш, TTL 5 минут, кулдаун на
  повторную отправку 60 секунд, лимит 5 попыток, одноразовое использование
  кода) уже реализован и покрыт тестами через `POST /api/v1/join-requests/send-code`
  и `POST /api/v1/join-requests/verify-code` — код просто нужно прочитать
  из консоли сервера вместо телефона, пока провайдер не подключён.
- Модель `SmsCode` в `prisma/schema.prisma` — уже в БД, миграция применена.

**Что сделать:**
1. Выбрать провайдера вместе с заказчиком (варианты, которые обычно
   используют в Казахстане: Mobizon, SMS.ru, либо международный Twilio).
2. Заполнить тело `sendSms()` в `cms/packages/api/src/lib/sms.ts` — вызов
   HTTP API провайдера. Сигнатура функции менять не нужно, вызывающий код
   (`join-requests.controller.ts`, `reminders.ts`) трогать не придётся.
3. Добавить реальные значения в `cms/.env` по образцу `cms/.env.example`:
   `SMS_API_KEY`, `SMS_API_URL`, `SMS_SENDER_NAME` (эти три переменные уже
   объявлены в `.env.example` как заготовка — можно переименовать/добавить
   свои, если у выбранного провайдера другой набор параметров).

**Как проверить:** зарегистрировать заявку через `/vstupit` до шага 4,
запросить код — раньше он был виден в логе `npksite-cms-api`
(`SMS provider not configured — skipping SMS to +7...`), после интеграции
должен реально прийти на телефон.

## 2. Google Meet / Calendar API (видеоприём)

**Где используется:** приёмная `/priemnaya`, режим «Видеоприём» — менеджер
в CMS назначает созвон с депутатом, гражданину должна автоматически прийти
ссылка на Google Meet на почту.

**Что уже сделано:** миграции БД (`Appeal.format`, модель `AppealMeeting`),
экран в CMS-админке (выбор депутата и времени, статусы, кнопка «Скопировать
для WhatsApp»), письмо гражданину (уже реально отправляется через
`sendMail`), эндпоинты `PUT`/`DELETE /cms/api/v1/appeals/:id/meeting`,
фоновое email-напоминание за час (`node-cron`, `reminders.ts`).

**Что сделать:** реализовать две функции в
`cms/packages/api/src/lib/googleCalendar.ts` (`createGoogleMeetEvent()` и
`cancelGoogleMeetEvent()`) и заполнить `GOOGLE_CLIENT_ID` /
`GOOGLE_CLIENT_SECRET` / `GOOGLE_REFRESH_TOKEN` / `GOOGLE_CALENDAR_ID` в
`cms/.env`.

**Подробная пошаговая инструкция (Google Cloud Console, OAuth consent,
получение refresh token, что именно писать в коде):** см.
[`docs/GOOGLE_MEET_SETUP.md`](GOOGLE_MEET_SETUP.md) — там расписано целиком,
здесь не дублируем.

Пока переменные не заполнены, встреча в CMS сохраняется со статусом
`PENDING` вместо `SCHEDULED` (без падения с 500) — можно тестировать всё
остальное уже сейчас.

## 3. YouTube Data API v3 (секция «Народное медиа» на главной)

**Где используется:** карусель последних роликов на главной странице
(секция `NarodnoeMediaSection`, сразу под новостями).

**Что уже сделано:** `GET /api/v1/youtube/feed` в
`cms/packages/api/src/modules/youtube/youtube.controller.ts` — дёргает
YouTube Data API v3, кэширует ответ на 6 часов (модель `Setting`,
`key=youtube_feed_cache`). Без ключа или при ошибке API отдаёт то, что есть
в кэше, иначе фронт остаётся на статичном фолбэке — сайт никогда не падает.

**Что сделать:** один ключ, без доступа к самому каналу партии.
1. console.cloud.google.com → любой проект (можно тот же, что для Calendar
   API выше) → APIs & Services → Library → включить «YouTube Data API v3».
2. Credentials → Create Credentials → API key.
3. Вписать в `cms/.env`: `YOUTUBE_API_KEY=<ключ>`.

`YOUTUBE_CHANNEL_ID` в `.env.example` уже проставлен на канал НПК —
трогать не нужно, если не сменится канал.

**Как проверить:** после того как ключ вписан в `cms/.env` — перезапустить
`npksite-cms-api`, обновить главную страницу, в секции «Народное медиа»
должны появиться реальные последние ролики канала вместо статичной заглушки.

- [ ] SMS: выбрать провайдера, заполнить `sms.ts`, добавить `SMS_API_KEY` и т.п. в `cms/.env`
- [ ] Google Meet: реализовать `googleCalendar.ts` по `docs/GOOGLE_MEET_SETUP.md`, заполнить `GOOGLE_*` в `cms/.env`
- [ ] YouTube: получить `YOUTUBE_API_KEY`, вписать в `cms/.env`

Все три пункта независимы друг от друга — можно делать в любом порядке или
параллельно, ничего не блокирует остальной сайт (везде есть фолбэки/dev-режим).
