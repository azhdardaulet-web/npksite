## Важное расхождение схемы

В поставленной задаче названы Supabase-таблицы с полями `*_kz`. В текущем репозитории `supabase/` отсутствует, а активная схема находится в `cms/packages/api/prisma/schema.prisma` и использует PostgreSQL/Prisma:

| Ожидаемый адресат из задачи | Фактический эквивалент в текущей Prisma-схеме |
|---|---|
| `page_blocks.*_kz` | `PageBlock.content` (JSON с ключами `...Kz`) и `PageTranslation(lang='kz')` |
| `program_blocks.*_kz` | `ProgramBlockTranslation(lang='kz').title/lead1/lead2/points`; у `keyword` отдельного KZ-поля нет |
| `appeal_topics.name_kz` | `AppealTopic.nameKz` |
| `branches.city_kz/address_kz` | `Branch.cityKz/addressKz`; отдельного `chairmanKz` нет |
| `menu_items.label_kz` | `MenuItem.labelKz` |
| `history_events.*_kz` | `HistoryEventTranslation(lang='kz').title/text` |
| `leaders.*_kz` | `TeamMemberTranslation(lang='kz').name/position/bio/fullBio` |
| `site_settings.*_kz` | `Setting.value` не языковой; часть локализуемых настроек лежит в `PageBlock.content` |
| `news.*_kz` | `NewsTranslation(lang='kz').title/excerpt/content/...` |

Ниже используются имена адресатов из задачи как контракт для этапа 2. До генерации SQL нужно подтвердить фактическую DDL-схему Supabase или согласовать миграции под Prisma.
