# Архитектура сайта «Народная партия Казахстана» (НПК)

> Документ для проектирования CMS/CRM. Составлен на основе реального кода React/TypeScript SPA (React Router). Для каждой страницы указаны: секции, кнопки/ссылки, формы, динамические массивы данных (потенциальные CMS-сущности) и точки лидогенерации (потенциальные CRM-сущности).
>
> **Технический стек:** React 19 + TypeScript + React Router v6 + Tailwind CSS. Один общий layout (`PageLayout`) с хедером/футером на всех страницах. Данные сейчас хардкожены в коде (частично централизованы в `src/lib/data.ts`, частично разбросаны по страницам/секциям).

## 1. Централизованный источник данных `src/lib/data.ts`

Общий файл с массивами, которые переиспользуются на нескольких страницах — **первые кандидаты на таблицы в БД**.

### `candidates` — Кандидаты (6 записей)
Поля: `{ id, name, region, district, promise, photo }`
Пример: `{1, 'Ерлан Смагулов', 'Алматы', 'Округ №4', 'Доступное жилье для каждой семьи...', '/images/candidate-1.jpg'}`

### `regions` — Филиалы/регионы (20 записей: 3 города + 17 областей)
Поля: `{ id, name, chairman, address, phone }`
Пример: `{'astana', 'Астана', 'Нурлан Сагинтаев', 'пр. Кабанбай батыра, 18', '+7 7172 70 12 34'}`
> Примечание: параллельно на главной странице (`BranchMapSection`) используется расширенная версия того же справочника — 20 записей с полями `{ name, short, city, lng, lat, chairman, email, address, phone }` (добавлены координаты для карты и email). Рекомендуется свести в единую сущность «Филиал».

### `newsItems` — Новости (6 записей, укороченная версия для главной)
Поля: `{ id, date, title, image, category, readTime }`

### `testimonials` — Отзывы (3 записи)
Поля: `{ id, quote, author }`

### `socialStats` — Статистика соцсетей (5 записей)
Поля: `{ platform, subscribers, icon }`

### `regionFilterTags` — Список тегов-регионов для фильтра (21 строка, включая «Все»)

### `ELECTION_DATE` — Константа даты выборов (2026-07-01)

## 5. Сводка: точки лидогенерации для CRM

| Форма | Страница | Поля | Статус backend |
|---|---|---|---|
| **Заявка на вступление** | `/vstupit` (JoinPage) | роль (member/volunteer/observer), ФИО, телефон, email (необязательно), город | ⚠️ не подключена — только локальный state |
| **Заявка на вступление (дубль)** | Главная (JoinSection) | ФИО, телефон, согласие | ⚠️ не подключена |
| **Обращение гражданина** | `/priemnaya` (ReceptionPage) | имя, телефон, тема (select), сообщение | ⚠️ не подключена |
| **Обращение гражданина (дубль)** | Главная (ReceptionSection) | имя, телефон, тема, сообщение, согласие | ⚠️ не подключена |
| **Подписка на открытие магазина** | `/magazin` (ShopPage) | email | ⚠️ полный no-op, даже локально не обрабатывается |
| **Кнопка «Поддержать» кандидата** | CandidatesPage, главная | — | ⚠️ не реализована (нет onClick) |

**Вывод:** на сайте есть 2 уникальные формы лидогенерации (вступление в партию и обращение гражданина), каждая дублируется на главной странице и на отдельной странице. Обе сейчас **полностью фронтенд-имитация** без реального сохранения данных — при проектировании CRM это первое, что нужно реализовать (API endpoint + таблицы «Заявки на вступление» и «Обращения граждан», с полями ролей/тем как справочниками).
